JA ⇄ EN · game localization QA · prototype

訳の「揺れ」を、
プレイヤーより先に。 Catch the drift before your players do.

Kotomark は日英ゲームローカライズ向けの台本全体の一貫性チェックです。用語、カタカナ表記、キャラ名、敬称、口調が台本のどこで揺れているかを、ファイル名と行番号付きで指摘します。

Kotomark checks a whole Japanese↔English game script for consistency. It finds where terms, katakana spellings, character names, honorifics and character voices drift, and points to each case by file and line.

デモを試すTry the demo 試用協力者を募集中Looking for pilot partners

デモはブラウザ内だけで動きます。台本ファイルはどこにも送信されません。サンプル台本入り。

The demo runs entirely in your browser. Your script files are not uploaded anywhere. Sample script included.

Instead of checking one segment at a time, it compares the whole script with itself and finds where things drift. Every example below is real output from the bundled sample script (samples/ja-en, invented text).

ルールで決めきれない行は「レビュー用パケット」に。「この行はまだ彼女らしいか」「用語集にない頻出語」など、判断が要る箇所は必要な行だけをまとめて返し、あなたのAIアシスタントと担当者が判断します。最終判断は人が行います。

Lines the rules can't judge become review packets. “Does this still sound like her?” or a recurring term that isn't in the glossary: Kotomark bundles just the lines needed, and your own AI assistant and your reviewers make the call. A person makes the final decision.

日本語の解析は正規表現ベースのヒューリスティックです（形態素解析は使っていません）。見逃しや誤検出があり得るため、口調の指摘は「警告」「情報」にとどめています。

Japanese analysis is heuristic and regex-based (no morphological analyzer). It will miss or misread some lines, which is why voice findings stay at warning or info level.

どれも同じ検査エンジンです。結果はすべて ファイル名:行番号 付きで返ります。

All three use the same engine, and every finding comes back with file:line.

ブラウザのデモBrowser demo

インストール不要。ファイルをドラッグ＆ドロップすると、ブラウザの中だけで検査します。まず感触を確かめたい方に。

Nothing to install. Drop in your files and the check runs inside your browser. The quickest way to get a feel for it.

B · CLI

コマンドラインCommand line

手元のパソコンだけで動き、通信しません。終了コード（0 問題なし／1 エラーあり／2 入力不正）でCIにも組み込めます。

Runs on your own machine with no network calls. Exit codes (0 clean / 1 errors / 2 bad input) make it CI-friendly.

  --glossary glossary.json
C · MCP

いつものアシスタントから /lqa-check で実行。決まった検査はサーバーが行い、判断が要る行の検討はあなたのアシスタントが行います。

Run /lqa-check from the assistant you already use. The server does the rule-based checks; your assistant works through the lines that need judgment.

あなたのAIアシスタントYour AI assistant ファイルを読み、レビュー用パケットを判断し、最終レポートを書く。推論はあなた自身の契約の範囲で動きます。 Reads your files, judges the review packets, writes the final report. Reasoning runs on your own subscription.
⇄ MCP

Designed on the assumption that your script is under NDA.

MCP 経由の台本はメモリ上で検査し、結果を返したら破棄します。ディスク・データベースには書きません。

Scripts sent over MCP are checked in memory and discarded once the result is returned. Nothing is written to disk or a database.

Logs hold only method, path, status, user ID and timing. No text, file names or terms (covered by automated tests).

用語集は選んだときだけ保存Glossaries saved only if you choose

チームで共有したい用語集だけ、1件ずつ AES-256-GCM で暗号化して保存します。いつでも削除できます。

Only glossaries you choose to share with your team are saved, each encrypted with AES-256-GCM. Delete them any time.

当社サーバーがAIモデルを呼ぶ機能（一括処理向け）は初期状態でオフです。

Server-side AI judging (for batch use) is off by default.

07

よくある質問FAQ

どのファイル形式に対応していますか？Which file formats are supported?

台本は CSV / TSV（1行目に列名が必要）、Excel（.xlsx）、JSON（ja.json と en.json のような言語別ファイルを含む）、XLIFF 1.2 / 2.0、gettext（.po）、YAML のロケールファイル、Ren'Py の翻訳ファイル、KAG / TyranoScript（.ks）、Unity・Unreal の文字列テーブルです。用語集は JSON、CSV / TSV（Crowdin・Phrase などの書き出し）、TBX です。複数のファイルをまとめて検査できます。

Scripts: CSV / TSV (header row required), Excel (.xlsx), JSON (including per-language files such as ja.json + en.json), XLIFF 1.2 / 2.0, gettext (.po), YAML locale files, Ren'Py translation files, KAG / TyranoScript (.ks), and Unity / Unreal string tables. Glossaries: JSON, CSV / TSV (e.g. Crowdin or Phrase exports) or TBX. You can check several files together.

用語集が無くても使えますか？Do I need a glossary?

カタカナの表記揺れ、話者ラベルの書き方の揺れ（大文字・小文字、ひらがな・カタカナなど）、プレースホルダー、タグ、ルビ、文字数は用語集なしで検出します。「MINA」と「ミナ」のように書き方が別の話者ラベルを同じキャラと見なすには、用語集のキャラ設定が必要です。用語の訳揺れ・敬称・口調の検査には用語集（キャラ設定）が必要です。台本から用語集の下書きを作る機能がありますが、推定なので必ず見直してください。

Katakana notation, speaker-label spelling (case, hiragana vs. katakana and so on), placeholders, tags, ruby and length are checked without one. Matching labels written differently, such as “MINA” and “ミナ”, needs character entries in the glossary. Term, honorific and voice checks need a glossary with character profiles. Kotomark can draft a glossary from your script, but the draft is heuristic, so always review it.

日→英と英→日の両方に使えますか？Does it work in both directions?

言語の向きはテーブルごとに自動で判定し、日本語側の検査は日本語の側に対して行います。ただし敬称と口調の検査は、日本語の原文を英語に訳すケースを中心に作っています。

Direction is detected per table, and the Japanese-side checks run on whichever side is Japanese. The honorific and voice checks are built mainly around Japanese source rendered in English.

LQAテスターの代わりになりますか？Does it replace LQA testers?

なりません。台本全体から揺れを探す作業を速くするための補助です。その行が正しいか（文脈、意図、口調）を決めるのは人です。

No. It speeds up finding drift across a whole script. Deciding whether a line is right (context, intent, tone) is still a person's job.

どのAIアシスタントで使えますか？Which AI assistant do I need?

現在、Claude Code 用のプラグインで試しています。ブラウザのデモとCLIはAIアシスタントなしで使えます。Kotomark は独立した製品で、AI提供元とは提携していません。

We're currently testing with a Claude Code plugin. The browser demo and the CLI work without any AI assistant. Kotomark is an independent product and is not affiliated with any AI provider.

誤検出はありますか？Will it flag things that aren't problems?

あります。たとえば名前と1文字違いの実在の英単語を指摘することがあります（除外リストに追加できます）。どのくらい出るかを、試用協力者の方と一緒に測っているところです。

Yes. For example, a real English word one letter away from a character name can be flagged (you can add it to an ignore list). Measuring how often this happens is exactly what the pilot is for.
