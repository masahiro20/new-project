## 3. B-02 の測定

合成データ（`test/stress-data.ts`：日本語の用語、1行に0〜3語、半分は正しい訳、1割に禁止訳語）。同じマシン、`runChecks` 全体。

| 規模 | 修正前 | 修正後 |
|---|---|---|
| 1,000語 × 5,000行 | 6.5秒 | 0.8秒 |
| 2,000語 × 10,000行 | 32.1秒 | 1.2秒 |
| 5,000語 × 50,000行 | 用語の検査だけで 414秒、メモリ 3.2GB | 4.6秒（検査全体）、メモリ 0.19GB。指摘 37,419件で修正前と同一 |
| キャラクター 200 × 20,000行（名前の検査） | 12.3秒 | 0.6秒 |
| 1,000語＋キャラクター100 × 10,000行（回帰テストの条件） | 約14.5秒（用語・パケット・名前） | 約1.0秒 |

- サーバーの上限いっぱいの例（修正後）：1,000語＋キャラクター1,000 × 100,000行 で 7.2秒、キャラクター2,000 × 100,000行 で 5.6秒（CLI の条件。サーバーではキャラクターは1,000まで）、
  用語集なし・カタカナの表記揺れだらけの 100,000行 で 4.9秒。時間予算 20秒は、共有 CPU の遅いマシンでも正当な最大規模の検査を切らない値として選んだ。
- 修正前は「用語×行」の真偽値の表（5,000×50,000 で 2.5億要素）も持っていた。修正後は一致した行だけを持つ。
- 回帰テスト（`test/limits.test.ts` の perf）は 1,000語＋キャラクター100 × 10,000行を 6秒未満で判定（通常は約1秒。修正前の実装なら約14秒で落ちる）。遅いマシンでは `KOTOMARK_SKIP_PERF=1` で省略できる。
- 結果が変わらないことは、修正前の `terms.ts`・`names.ts`・`voice.ts`・`draft.ts` と、合成データ・英語の用語（複数形・所有格・大文字・アポストロフィ）・見本で出力を突き合わせて確認した。
