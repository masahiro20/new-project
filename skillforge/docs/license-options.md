**前提：** Action は公開リポジトリ `kotomark-action`（[repo-migration.md](repo-migration.md) 案 B）に置き、CLI 全体のバンドル `dist/kotomark.mjs`（minify なし＝ロジックは読める）を同梱します。

## 比較

## 推奨

**Action のラッパー（`action.yml`、`run.sh`）は MIT。エンジンのバンドルは Elastic License 2.0。有料プランはオフラインで検証するキーで開放する。**

- **無料枠：** 個人・小規模チーム・OSS プロジェクトが普段使いで困らない上限（例：1回あたり N 行、または公開リポジトリなら無制限）。上限は製品自体が守らせ、回避は ELv2 で禁止されます。
- **有料：** キー（Solo / Studio）で上限を外します。ホスティングする MCP と共有用語集は、手軽さに対する有料オプションにします（MCP はすでにトークンと上限がある）。
- **理由：**
  1. データ方針「台本を外へ出さない」と、ローカライズ会社の NDA の両方を守れる。(C) はこれを壊す。
  2. ELv2 は「キーの回避」と「ホスティングしての再提供」を条文で禁止しているので、JS を書き換えればキーを外せるという弱点を、契約の面で補える。独自 EULA (B) より文面の作成と相手方の法務確認が軽い。
  3. 実装は 3〜5日。あとから緩める（無料枠を広げる、MIT にする）ことはできるが、許諾的ライセンスで出してから締めることはできない。
- **代替案：** 「従業員数・売上で線を引きたい」なら PolyForm Small Business（キーは任意）。FSL と BSL は、標準の形では競合が同じものを作ることを防ぐだけで、一般の企業に支払いを求める根拠にならないので、単独では今回の目的に合いません。
- **書いてはいけないこと：** ELv2 / PolyForm は OSI 承認のオープンソースではありません。LP や README で「オープンソース」と書かず、「ソース公開」と書きます。
