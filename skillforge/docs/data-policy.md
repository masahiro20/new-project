# Kotomark（仮称）データ取り扱いポリシー（草案 v0.1）

> **草案です。** 公開前に法務の確認が必要です（利用規約・プライバシーポリシー・特商法表記と一緒に整えます）。
> ここに書いた約束は、すべて今のコード（`src/server/`）で守られています。コードと文書が食い違ったら、それはバグです。

## 1. 約束（要点）

| データ | 保存するか | どこに | どう守るか | 消し方 |
|---|---|---|---|---|
| **台本（文字列テーブル）** | **保存しません** | メモリ上だけ | 1回の検査が終われば破棄。ログにも残しません | 何もしなくて構いません |
| **検査結果・レポート** | **保存しません** | 呼び出し元に返すだけ | 同上 | 同上 |
| **用語集**（ユーザーが保存を選んだもの） | 保存します | 当社サーバーのディスク | AES-256-GCM で1件ずつ暗号化。名前も暗号化 | `delete_glossary`（1件、または全件） |
| **APIトークン** | ハッシュのみ保存 | トークンファイル | SHA-256。元のトークンは発行時に1回だけ表示 | 失効（`token revoke`） |
| **利用量**（行数・回数） | メモリ上の数値だけ | サーバーのメモリ | 台本の中身は含みません | 毎日 UTC 0時にリセット。再起動でも消えます |
| **アクセスログ** | 保存します | サーバーの標準出力 | 方法・パス・状態・ユーザーID・処理時間だけ | 保存期間は運用ルールで定めます（案：30日） |

## 2. 台本を保存しない

- 台本は MCP のツール呼び出し（`check_script` など）の引数として届きます。
- サーバーはそれをメモリ上で解析・検査し、結果を返したら破棄します。ディスク、データベース、キャッシュには書きません。
- サーバーは**状態を持ちません**（stateless）。リクエストごとにサーバーの実体を作り、終わったら捨てます。セッションもありません。
- ログに書くのは `POST /mcp 200 user=alice 12ms` の形式だけです。**本文・ファイル名・用語・エラーの中身は書きません**。
  - 例外的に、入力の形式エラー（例：「列が見つからない」）の文面はツールの結果として呼び出し元に返しますが、ログには書きません。
- 検査を速くするための内部キャッシュ（表示用テキストの変換結果、用語の照合パターン）はメモリ上だけにあり、**リクエストが終わるたびに消します**。ディスクには出ません。

## 3. 用語集の保存（任意）

- ユーザーが `save_glossary` を呼んだときだけ保存します。チームで同じ用語集を使えるようにするのが目的です。
- **暗号化：** 1件ごとに AES-256-GCM（96ビットのランダムIV、認証タグ付き）で暗号化します。
  - 用語集の**名前も暗号化**の中に入れます。ディスク上のファイル名は、ユーザーIDと名前の SHA-256 です。
  - ファイルの場所（ユーザー／名前）を改ざん検出の付加データにしているので、ファイルを別のユーザーの場所へ移しても復号できません。
- **鍵：** 環境変数 `KOTOMARK_ENCRYPTION_KEY`（32バイト、base64）。本番では必須で、無いとサーバーは起動しません。
  - 開発時だけ、データ置き場に鍵ファイルを自動で作ります。
  - **公開前の課題：** 鍵をクラウドの鍵管理サービス（KMS）に置き、定期的に入れ替える手順を決めます。
- **削除：**
  - `delete_glossary`（名前指定）で1件、`delete_glossary`（`all: true`）で全件を、その場で完全に削除します。
  - 解約時は全件を削除します（運用手順として実施）。
  - **公開前の課題：** バックアップを取る場合、バックアップからも一定期間内に消えることを明記します。
- **上限：** 1件 2MB まで。件数は Solo 10件、Studio 50件。
- **差し替え可能な設計：** 保存先は `GlossaryStore` という共通の窓口を通しています。今はローカルのディスクですが、データベースやオブジェクトストレージに差し替えても、ツールの側は変わりません。

## 4. 推論（AIによる判断）について

- 判断が要る箇所（口調など）は「レビュー用パケット」としてユーザーの手元に返し、**ユーザー自身の AI アシスタント**が判断します。当社はその判断を見ません。
- 当社のサーバーがAIモデルを呼ぶ機能（一括処理向け）は**初期状態でオフ**です。
  - 有効にした場合も、当社のAPIキーを使います。ユーザーの認証情報は受け取らず、中継もしません。
  - 有効にした場合、レビュー用パケットの文字列がモデル提供元（Anthropic）に送られます。その場合の扱いは提供元の商用利用条件に従います。有効にする前に、この文書と利用規約に明記します。

## 5. アクセス制御と利用制限

- 利用者ごとにAPIトークンを発行します（`kotomark token create <user> --plan solo|studio`）。
  - 保存するのはハッシュだけです。トークンの先頭10文字だけは識別用に残します。
- 他の利用者の用語集は、名前を知っていても読めません（保存場所が利用者ごとに分かれ、暗号化の付加データにも利用者IDが入っています）。
- 利用制限（外部サービスなしで動きます）：

| プラン | リクエスト／分 | 検査できる行数／日 | 保存できる用語集 |
|---|---:|---:|---:|
| Solo | 30 | 200,000 | 10 |
| Studio | 120 | 1,000,000 | 50 |

- 超えた場合は HTTP 429 と `Retry-After` を返します。行数の上限を超えたリクエストは数えません（検査もしません）。
- **公開前の課題：**
  - サーバーを複数台にする場合は、利用量の数値を共有の保存先（例：Redis）に移します。
  - トークン方式から OAuth に移ります。
