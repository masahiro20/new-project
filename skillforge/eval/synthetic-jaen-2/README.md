## 方法

1. **clean の確認**：`script_clean.csv` を G・A の両方で検査した。G で 8 件、A で 5 件の指摘が出たが、**すべて「紛らわしいが正しい」として意図して書いた行**の上だった（下の表）。それ以外の行には指摘がなかったので、台本の修正はしていない。
2. **埋め込み**：`node eval/synthetic-jaen-2/inject.mjs`。14 カテゴリ 78 件。操作はどれも単純な文字列の置換で、乱数で決めるのは 1 件（EN のつづり違いの候補 2 つからの選択）だけ。
3. **検査**：`script_drifted.csv` を G（`--glossary glossary.json`）と A（`--no-glossary`）で検査した。
4. **採点**：`score.mjs`。正解行（±0）に、そのカテゴリに対応するルールの指摘があれば「発見」とした。重大度は問わない（警告以上に限った数も併記）。対応表（`CATEGORY_RULES`）は、JSON 出力のルール名の意味だけから決めた。たとえば `pronoun` には `voice.first-person` が対応し、`katakana` には `notation.katakana` と `term.*` が対応する（EN 側のつづり違いは用語の逸脱として出るため）。
   - 精度：正解行の指摘は TP、紛らわしい行の指摘は FP とした。それ以外の行の指摘は評価者が手で判定した（`JUDGEMENTS`）。今回、判定が必要だったのは 1 件だけ。

```bash
cd skillforge
node eval/synthetic-jaen-2/inject.mjs
S=/tmp/claude-0/eval/s2; mkdir -p $S; D=eval/synthetic-jaen-2
for f in clean drifted; do
  npx tsx src/cli/index.ts check $D/script_$f.csv --glossary $D/glossary.json --format json --fail-on never > $S/$f.G.json
  npx tsx src/cli/index.ts check $D/script_$f.csv --no-glossary          --format json --fail-on never > $S/$f.A.json
done
node $D/score.mjs --truth $D/truth.csv --clean-G $S/clean.G.json --drifted-G $S/drifted.G.json \
  --clean-A $S/clean.A.json --drifted-A $S/drifted.A.json --out $D/results.json
```

エンジンは 2026-10-09 時点の skillforge 作業ツリー（この評価で src/ は変更していない）。

## 見逃しと誤検知から見える改善点（ソースは見ずに、挙動だけから書いたもの）

1. **一人称の誤検知（5 件、すべて警告）が最大の問題。** 『』「」の中の一人称は、引用か、語そのものへの言及であることが多い。そのため、プロフィールとの照合から外すか、情報レベルに下げるべき。また「うちの＋名詞」（うちの部、うちの学校）は所有の意味の「うち」なので、一人称から除くべき。どちらも、日本語の台本では日常的に出てくる形。
2. **ルビの破損が 0/3。** `{漢字|かな}` の閉じ忘れ、全角の `｜`、空の読みを検出していない。clean 側でルビが正しく除かれているかは、今回の指摘からは判断できない（ルビ入りの行で用語の誤検知は出ていない）。エンジンにルビの検査がない、または `{…|…}` 以外の記法を想定している可能性がある。
3. **原文がそのまま入った訳（EN 欄が JA のまま）と、隣の行のコピーを検出しない。** 空欄だけが `untranslated.empty` になる。EN 欄にかなや漢字が含まれる、EN が別の JA の行の EN と完全に一致する、といった単純な規則で拾えるはずの、実務でよくある事故。ただし、"Q.E.D." のような記号・略語の一致は除外が必要（今回は正しく何も出ていない）。
4. **カタカナ表記揺れ（JA）の 2 種。** 「フイルム／フィルム」（イとィの大小）と、ひらがなの「ぺ」とカタカナの「ペ」の混入（見た目では区別できない典型的な誤り）を見逃している。長音の脱落（サーバ／サーバー）と中黒（クロノ・グラフ）は検出している。
5. **話者ラベルのひらがな表記（しおり → 詩織）** を見逃している。第 1 弾の `りん` と同じ型。
6. **register の自然な切り替え**（常体のキャラが目上にだけ丁寧語を使う）が警告になる。プロフィールの `politeness` は「同輩・目下に対して」の既定と解釈し、「先生」「先輩」などの呼びかけがある行は情報レベルに下げる案が考えられる。
7. **部室棟 → club building**：用語「部室」が、より長い語「部室棟」の一部として一致している。用語の照合で、より長い既知の複合語（または、前後が漢字で続くこと）を考慮しないと、日本語では誤検知が出やすい。

## 限界（必ず併記すること）

- **合成データは実データではない。** 文は短く、1 行に誤りは 1 件だけ。誤りが多数派になる場合（揺れの方が多い）や、1 行に複数の誤りがある場合は試していない。実際の台本の量、文体の幅、地の文の割合とも違う。
- **作者のバイアス**：今回はエンジンのソースを読んでいない。ただし、第 1 弾の README（ルール名と、前回の見逃しの例）は読んだうえで作っている。そのため、「前回見逃した型」（ひらがなの話者ラベル、名前を落とした呼び方、同数の多数決）を意識して入れた誤りがある。また、clean で最初から誤検知が 0 件だった行は、作者の書き方の癖にエンジンが合っているだけかもしれない。
- **「紛らわしいが正しい」行の判断は評価者 1 人**による。とくに s2_027（先生への敬語）と s6_029（呼び捨て）は、指摘があってもレビュアーによっては許容範囲と考えるかもしれない。s6_029 は情報レベルで「意図的か確認せよ」という内容なので、実害は小さい。
- カテゴリとルールの対応は、ルール名の意味から評価者が決めた。対応の判断を変えると数字は変わる。ただし今回は、正解行の上で別のルールだけが出た例（`lineOnly`）は 0 件で、対応表の影響はなかった。
- 英語側の口調（タメ口化、キャラらしさ）は、ルールでは短縮形と禁止語しか見ていない。それ以外は利用者側の AI が判断する部分（レビュー用パケット）で、ここでは測っていない。
- 埋め込みの多くは 1 回限りの置換で、各カテゴリの件数は 2〜10 件と少ない。カテゴリ別の再現率は ±1 件で大きく動く。
