# 鋼脚戦機 GRANDSTRIDE 収益化計画書

- 作成: P8 Mech Game 収益化担当 / 2026-10-08
- 前提: オーナーは日本在住の個人、Claude Code Max プランで開発、資金は少ない。本部方針（小さく出す・数字で判断・ステージゲート・build in public）に従う。
- 為替は **1ドル = 150円** で換算（概算）。数字の後ろの「推定」は、公開データからの推計か、担当者の見立てを意味する。出典は各所と末尾にまとめた。
- 設定上の用語は `world-bible.md` に従う（鞍士・共鳴率・脚圧・炉温・灰殻など）。

## 1. 結論

1. **最初の売上はブラウザ版から取る。** 2週間以内に、1ミッション（5〜10分）だけ遊べる無料ブラウザ版を **itch.io（投げ銭あり）** に出し、続けて **CrazyGames（独占なし・登録無料）** に出す。現金の出費はゼロ。最初の1ドルは itch の投げ銭、継続収入は CrazyGames の広告収益分配から入る見込み。
2. **本命は Steam の「無料デモ＋本編買い切り（Early Access で $9.99 前後）」。** ただし Steam の $100 を払うのは、Web で「遊ばれる」証拠（itch・CrazyGames の数字。§5 のゲート）がそろってから。目標は **2027年6月の Steam Next Fest にデモで出て、その後に Early Access を出すこと**（日程は推定）。
3. **スマホ版、F2P＋課金、ガチャは今はやらない。** スマホ版は Steam で売れてから、買い切りか広告付き無料で出す。ガチャはやらない（法規制・評判・運営の負担が理由）。
4. Poki は「Web 独占で5年」が基本条件なので、最初は選ばない。CrazyGames で数字が良く、Poki から声がかかったときにオーナーが判断する。

## 6. マーケティング

**基本の方針:** 英語を先に、日本語も同時に出す。「四本脚が地面を踏みしめる重さ」と「脚圧が0になって機体が崩れる瞬間」が、このゲームで一番伝わる絵。すべての投稿をこの2つに集中させる。

| 場所 | 何を | 頻度・注意 |
|---|---|---|
| **X（英語＋日本語）** | build in public。開発の数字（プレイ数、wishlist）を正直に出す。15〜30秒の動画: 着地の衝撃、脚圧が切れて転倒、炉温が上がって強制冷却、OVERBEAT への突入。ハッシュタグ #gamedev #indiedev #ScreenshotSaturday #mecha #threejs / #インディーゲーム #ロボットゲーム | 1日1本。金曜は Reddit と同じ素材を使い回す |
| **YouTube Shorts / TikTok** | 縦 9:16 の15秒。最初の1秒で「足元のアップ → 鞍座からの視点」。字幕は英語。音（足音と装甲のきしみ）を大事にする | 週3本。同じ動画を両方に出す |
| **Reddit** | r/mechagaming（メカ好き）、r/Mecha、r/WebGames（ブラウザ版）、r/threejs（技術の話）、r/IndieDev、r/indiegaming。各サブレディットのルール（宣伝の頻度）を守る | 1つのサブレディットに月1〜2回。宣伝だけでなく、技術の話や質問への返事を多くする |
| **日本のロボットアニメ好き** | 日本語の X、pixiv FANBOX（設定画・機体の三面図を支援者に公開）、デジゲー博・BitSummit への出展（出展料と交通費がかかるので、Steam のページができてから判断）。「全高28mの四脚機」という作り込んだ設定を前に出す | 既存作品の名前でタグ付けや比較をしない（§7） |
| **海外のメカ好き** | MechWarrior、Armored Core、Titanfall などを遊ぶ層。Steam のタグ（Mechs、Robots、First-Person、Action）を正しく付ける。メカゲームを紹介する YouTube 配信者・Steam キュレーターにデモの鍵を送る（Keymailer などの無料の範囲で） | 送るのは Steam のページができてから |
| **Webポータル（CrazyGames）** | それ自体が集客の場。終了画面に「Steam でウィッシュリスト」を置く（ポータルの規約で外部リンクが許される範囲で。要確認） | — |
| **自前サイト** | プレスキット、メール登録（発売のお知らせ）、Steam と itch へのリンク | ドメインを取ったとき |

## 7. リスクと対策

| リスク | 内容 | 対策 |
|---|---|---|
| **既存作品との類似（法的リスク）** | 「巨大な人型兵器＋神経がつながる操縦士＋謎の敵」はエヴァンゲリオンを思わせやすい。四足歩行メカは ZOIDS、脚の構成は Armored Core とも比べられやすい。アイデア自体は保護されないが、名前・デザイン・ロゴ・UI の表現を似せると問題になる | world-bible の禁止語を守る（すでに設定済み）。配色（紫と緑の組み合わせなど）、頭の角、円形の敵の輪、明朝体の大きな縦書きタイトルカードなど、特定作品を思わせる見た目を避ける。**ストアページや広告で他の作品名を使わない**（「〜風」「〜好きに」も避ける）。発売前に「GRANDSTRIDE」「グランドストライド」を J-PlatPat・USPTO・EUIPO で商標検索する。出願するかはオーナーが判断（日本で1区分なら出願料 約1.2万円、推定）。素材は CC0 か商用可のライセンスだけを使い、一覧を残す。Three.js（MIT）の表記を入れる |
| **Web 版の海賊コピー** | 単一 HTML は丸ごとコピーしやすく、勝手に他のサイトへ載せられる | **Web 版はデモ（第1作戦）だけにする。** 本編は Steam。ドメインの確認（サイトロック。ポータルの許可ドメインは入れる）[5]、コードの難読化は軽く。見つけたら DMCA の削除申請（テンプレートを用意）。追いかけすぎない（コピーは宣伝にもなる） |
| **Three.js 単一 HTML の限界** | 1ファイルが大きくなると保守が難しい。素材を埋め込むとサイズが増える。影・パーティクル・敵の数が増えると処理が重くなる。iframe 内でのマウス固定、iOS Safari の音声再開 [5] | 開発は分けたファイル（ES モジュール）で行い、**ビルドで単一 HTML を出力する**。モデルは手続き的な生成か、圧縮した glTF。描画の負荷（ドローコール数）を予算化する。Steam 版は Electron で包む（100MB 超になるので、軽い Tauri も検討）。WebGPU は後回し |
| **スマホの性能** | 一人称3D で端末が熱くなり、処理が落ちる。四本脚の操作をタッチでやるのは難しい。CrazyGames のモバイルトップ掲載は 20MB 以下 [5] | スマホは最後に回す。画面の解像度倍率の上限を 1〜1.5 にし、影を簡単にする。30fps 固定の選択肢。操作は「左で移動、右で照準、自動の脚圧補正」に単純化する。iOS のガイドライン 4.2 対策として、ネイティブ機能と通信なしでの動作を入れる [17] |
| **Steam で埋もれる** | 中央値の売上は非常に低い [13] | wishlist のゲートで Steam への投資を止められるようにする（§5）。Next Fest の参加は1作品につき1回だけ [22] なので、デモが固まってから出る |
| **AI 生成物** | Steam は AI で作ったコンテンツの申告を求める。海外のコミュニティは AI 生成アートへの反発が強い | コードは問題になりにくい。キービジュアルとカプセル画像は人が描く（外注）か、手作業で作る。申告は正直に行う |
| **税・お金** | 給与所得者の場合、副業の所得が年20万円を超えると確定申告が必要。海外からの支払いの源泉徴収 | itch と Steam で W-8BEN（租税条約）を提出する。売上と経費の記録を最初から残す。開業届と青色申告はオーナーが判断（売上が見えてからでも間に合う） |
| **開発の予算（Max の上限）** | 本部の他のプロジェクトと上限を取り合う | 各ゲートで数字が出ないときは、自動的に優先度を下げる |
