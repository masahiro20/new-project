# 評価協力の録音：受領・保管・削除の手順書

対象：P3 Pitch の「評価協力モード」で協力者が自分で書き出し、開発者に提出した zip（`Pitch-eval-YYYYMMDD.zip`）。
根拠：同意欄と zip の README.txt の約束「受領から90日で削除。それより前でも、依頼があれば7日以内に削除」。
Atlas のセキュリティレビュー（`peter-hq/qa/p3-security/REPORT.md`）の A-2・§7 への対応です。

- **この約束はコードでは守れません。** 開発者の手元に届いたあとは、この手順書と台帳だけが担保です。
- **本部の決定 d32：** 録音の収集は、Pitch が専用のオリジン（Cloudflare Pages）に移るまで始めません。
  この手順書は収集を始める前に整えておくためのものです。
- 台帳のひな形：`docs/ledger-template.csv`（本物の台帳はリポジトリに入れない。下の「台帳」）

## 0. 始める前に決めること（オーナーへのお願い）

| 項目 | いまの状態 | 決める人 |
|---|---|---|
| 提出と削除依頼の窓口（メールアドレスなど） | **未定（収集開始時に決定）**：窓口が決まるまで録音を受け取らない | オーナー |
| 受領・削除の担当（主・副の2人） | **未定（収集開始時に決定）** | オーナー・リーダー |
| 録音の保管場所（暗号化したフォルダ1か所） | **未定（収集開始時に決定）**：共有ドライブなどの、権限を絞れる場所 | オーナー |
| 台帳の置き場所（非公開。リポジトリの外） | **未定（収集開始時に決定）** | オーナー |
| バックアップの有無と保持期間 | **未定（収集開始時に決定）**：持つ場合は「90日以内に消える」設定にする（下の §5） | オーナー |

窓口が決まったら、同意欄・README.txt・プライバシーポリシー（`docs/privacy-policy-draft.md`）の「連絡先」を同じ値で埋めます。

## 1. 用語

- **提出物：** 協力者から受け取った zip 1つ。`manifest.json` の `exportId`（書き出しごとの乱数の番号）で見分けます。
  ファイル名の `rec-001-w0001` は協力者のあいだで重なるので、識別には使いません。
- **原本：** 受け取った zip と、それを展開したファイル（wav・json・manifest.json・README.txt）。
- **派生データ：** 原本から作ったもの。評価用のマニフェスト（`eval-real.mjs` に渡す `manifest.json`）、
  集計の CSV（`--csv results.csv`）、結果の表（`docs/eval-results.md` などに貼る前の表）、聞き取りの記録、
  プロットの画像、作業用のコピー。
- **バックアップ：** 保管場所の自動バックアップ、PC のバックアップ（Time Machine など）、メールの受信箱に残る添付。

## 2. 受け取るとき（受領）

1. 窓口に届いた zip を、保管場所の `受領/<exportId>/` にだけ保存する。受信メールの添付は保存後に削除する
   （メールのゴミ箱も空にする）。ダウンロードフォルダなどに残したコピーも消す。
2. `manifest.json` を開き、`exportId`・`count`・`build` を確かめる。`exportId` が無い zip（古い版）は、
   受領日と提出者の連絡手段から仮の ID（`legacy-YYYYMMDD-N`）を付け、提出者にその ID を伝える。
3. 台帳に1行足す（§4）。**削除予定日 = 受領日 + 90日**。
4. 提出者に受領を返信する（ひな形）：

   > 録音をお送りいただき、ありがとうございます。提出 ID は <exportId> です。
   > <削除予定日> までに削除します。それより前に削除をご希望の場合は、この ID を添えてご連絡ください。7日以内に削除します。

5. 同意文の版を記録する（§6）。

## 3. 使うとき

- 使ってよいのは、判定精度の検証と改善だけ（同意文の 1）。公開・第三者への提供はしない（同意文の 2）。
- 派生データを作ったら、どの `exportId` から作ったかを台帳の「派生データの場所」に書く。
  評価用のマニフェストには、各録音の行に `exportId` の列を入れる（削除のときに行を探せるように）。
- 結果を文書（`docs/eval-results.md` など）に載せるときは、件数・率などの集計だけにし、個々の録音・
  `exportId`・話者の情報は載せない。

## 4. 台帳

ひな形は `docs/ledger-template.csv`。**本物の台帳はリポジトリに入れず**、§0 で決めた非公開の場所に置きます。
台帳には提出者の氏名やメールアドレスを書きません（連絡は窓口のやり取りの中で行い、台帳は `exportId` で引く）。

| 列 | 中身 |
|---|---|
| exportId | manifest.json の exportId（無い場合は §2-2 の仮の ID） |
| 受領日 | YYYY-MM-DD |
| 削除予定日 | 受領日 + 90日 |
| 件数 | manifest.json の count |
| 同意文の版 | manifest.json の build と schema（§6） |
| 保管場所 | 原本のフォルダ |
| 派生データの場所 | 作ったものの場所（無ければ「なし」） |
| 依頼日 | 削除の依頼を受けた日（無ければ空） |
| 依頼の期限 | 依頼日 + 7日 |
| 削除日 | 実際に削除した日 |
| 削除者 | 削除した人 |
| 確認者 | 削除を確かめた人（削除者と別の人） |
| 備考 | 例外・連絡の経緯（個人情報は書かない） |

- **週に1回**（担当の主）、台帳で「削除予定日が7日以内」と「依頼の期限が近い」行を確かめる。
- 削除した行は、台帳から消さずに残す（削除した記録として）。行の中に録音の中身や個人情報は無い。

## 5. 削除の手順（90日の期限・依頼のどちらも同じ）

対象の `exportId` について、次の **すべて** を消します。**原本・派生データ・バックアップは同じ期限** です。

1. **原本：** 保管場所の `受領/<exportId>/` を削除し、ゴミ箱も空にする。
2. **派生データ：**
   - 評価用のマニフェストから、その `exportId` の行を消す（または作り直す）。
   - 集計の CSV・結果の表から、その `exportId` の行を消す。集計だけの数字（件数・率）は、次に評価を回すときに作り直す。
   - 聞き取りの記録・プロットの画像・作業用のコピーを消す。
3. **バックアップ：**
   - 保管場所のバージョン履歴・自動バックアップから消す。消せない仕組みなら、保持期間を「90日 − 受領までの日数」より短く設定しておく
     （例：保持30日。その場合、原本は「削除予定日の30日前」までに消す）。
   - PC のバックアップ・メールの受信箱とゴミ箱に残っていないか確かめる。
4. 台帳に **削除日・削除者** を書き、**別の人が** 2〜3 を確かめて **確認者** を書く。
5. 依頼による削除なら、提出者に完了を返信する（ひな形）：

   > ご依頼の録音（提出 ID <exportId>）を、<削除日> に削除しました（受け取ったファイル、評価のための作業データ、バックアップを含みます）。

## 6. 同意文の版の記録

提出物がどの同意文に基づくかを、zip の `manifest.json` の `build`（アプリのビルド：日付・コミット）と `schema` で残します。
同意文（同意欄と README.txt）を変えたら、下の表に1行足し、変更前に受け取った提出物には古い版の約束を守ります。

| 版 | 有効になったビルド | 主な内容 |
|---|---|---|
| eval-consent-1 | 2026-10-09 · 31a391d 以降（Atlas のパッチ 0001〜0003、d32 の修正） | 端末内は期限なし・自動では消えない。提出分は受領から90日で削除、依頼から7日以内に削除。exportId で依頼 |

受領時に、zip の README.txt の「開発者に渡す場合の同意文」が上の版と同じかを目で確かめ、違えば台帳の備考に書きます。

## 7. 依頼から7日以内に削除する流れ

| 日 | すること | 担当 |
|---|---|---|
| 依頼の当日（0日目） | 窓口で依頼を受けたら、台帳の行を `exportId` で探し、**依頼日** と **依頼の期限（+7日）** を書く。提出者に受付を返信する | 主 |
| 〜2日目 | §5 の手順で削除する（原本・派生データ・バックアップ） | 主 |
| 〜3日目 | 別の人が確かめ、台帳に **確認者** を書く。提出者に完了を返信する | 副 |
| 7日目 | 期限。主が不在でも副が §5 を行う | 副 |

- `exportId` がわからない依頼：受け取った日・件数・提出に使ったメールなど、提出者が示せる手がかりで探す。
  見つからない場合や、ほかの人の録音を消してしまうおそれがある場合は、確かめてから消す（期限内に返事をする）。
- **受付の返信ひな形：**

  > 削除のご依頼を受け付けました（提出 ID <exportId>）。<期限> までに削除し、完了をお知らせします。

## 8. 端末の中の録音（参考）

協力者の端末の中（ブラウザの IndexedDB）の録音には期限がなく、自動では消えません。協力者自身が
アプリの一覧（1件ずつ・すべて削除）か、ブラウザのサイトデータの消去で消します。開発者からは消せません。
