# 創設サポーターキーの運用手順

対象：P3 Pitch の「創設サポーター」（買い切り。本部の決定 d31）。購入は Ko-fi、キーは手作業で送ります。
キーは署名つきの文字列で、ページに埋め込んだ公開鍵だけで、端末の中で（オフラインで）確認します。

- 道具：`scripts/supporter-key.mjs`（Node 20 以降、依存なし）
- 公開鍵と取り消しリスト：`demo/supporter-pubkey.js`（リポジトリに入る。秘密の値は入らない）
- 秘密鍵：**リポジトリの外** の1か所だけ（PEM、権限 0600）。スクリプトはリポジトリの中への保存を拒否します。`.gitignore` にも `*.pem` などを入れてあります
- 価格・返金日数・Ko-fi の URL・無料枠の数字：`demo/supporter.js` の `PLAN`（ここだけ）

## 0. 始める前に決めること（オーナー・本部）

| 項目 | いまの値 | 場所 |
|---|---|---|
| 秘密鍵を持つ人・保管場所・予備（バックアップ） | 未定（本番の鍵ペアは未作成） | — |
| Ko-fi の商品ページの URL | 空（画面は「準備中」） | `PLAN.kofiUrl` |
| 価格の表示 | `$19`（買い切り） | `PLAN.price`, `PLAN.priceNote` |
| 返金 | 30日以内なら理由を問わず | `PLAN.refundDays` |
| 無料枠 | 1日20語・最小対5組・記録7日（仮置き） | `PLAN.free*` |
| 販売前から無料枠を適用するか | 適用する（`true`） | `PLAN.freeLimitsActive` |
| プライバシーポリシー | Ko-fi で購入者のメールアドレスを扱うため更新が必要 | 法務 |

## 1. 鍵ペアを作る（最初に1回だけ）

秘密鍵を持つ人の端末で：

```sh
cd pitch
node scripts/supporter-key.mjs init --key ~/.config/p3pitch/supporter-key.pem
```

- 秘密鍵が `~/.config/p3pitch/supporter-key.pem`（0600）に、公開鍵が `demo/supporter-pubkey.js` に書かれます。
- 秘密鍵は、パスワード管理ツールなど **リポジトリの外** に予備を1つ取ります。なくすと新しいキーを発行できません
  （作り直すと、それまでに発行したキーがすべて使えなくなります）。
- `demo/supporter-pubkey.js` をコミットし、`npm run build:demo` と `npm run build:pwa` で公開用のページを作り直します。
  公開鍵が入るまで、ページのキー入力欄は「準備中」で、何も解除しません。
- `PLAN.kofiUrl` に Ko-fi の商品ページの URL を入れます（空のあいだは「購入ページは準備中です」）。

すでに公開鍵があるファイルへの `init` は拒否します（`--force` で置き換えると、発行済みのキーはすべて無効）。

## 2. キーを発行する（購入1件ごと）

```sh
node scripts/supporter-key.mjs issue --key ~/.config/p3pitch/supporter-key.pem --serial 1
# → PITCH-04000-0010F-…（1行。これを送る）
```

- `--serial`：通し番号。1 から順に、**同じ番号を2回使わない**。
- `--date YYYY-MM-DD`：発行日（省略時は今日・UTC）。`--flags N`：将来用の機能フラグ（省略時 1）。
- 秘密鍵と `demo/supporter-pubkey.js` の公開鍵が対でない場合や、取り消し済みの番号の場合は発行しません。
- キーには氏名やメールアドレスは入りません。

**台帳**（リポジトリの外、例：本部の非公開の表）に1行ずつ残します：
通し番号・発行日・Ko-fi の注文番号・送付日・返金の有無。メールアドレスは Ko-fi 側に残るので、台帳には書かなくて構いません。

## 3. Ko-fi で購入されたら（手作業）

1. Ko-fi の通知（または管理画面の注文）を確認する。
2. 台帳で次の通し番号を決め、`issue` でキーを作る。
3. `verify` で確認する：`node scripts/supporter-key.mjs verify "<キー>"` → `OK serial=…`。
4. Ko-fi のメッセージ機能（または購入者のメール）で、本部が用意する文面にキーを貼って送る。文面の例：

   > 創設サポーターへのご購入、ありがとうございます。サポーターキーは次のとおりです。
   >
   > PITCH-…（キー）
   >
   > Pitch のページ下の「創設サポーター」にある欄に、キーをそのまま貼り付けて「キーを確認して解除」を押してください。
   > 使う端末（スマホ・PC）ごとに貼り付けが必要です。判定はベータで調整中で、精度を約束するものではありません。
   > 購入から30日以内なら、理由を問わず返金します（このメッセージにご返信ください）。

5. 台帳に送付日を記入する。

キーは空白・改行・小文字・全角・ハイフンの有無が混じっても通ります。届かない・通らないという問い合わせには、
`verify` で確認してから同じキーを送り直します（新しい番号は不要）。

## 4. 取り消す（返金・不正な共有など）

```sh
node scripts/supporter-key.mjs revoke --serial 12
npm run build:demo && npm run build:pwa   # 公開用のページを作り直して公開する
```

- `demo/supporter-pubkey.js` の `REVOKED_SERIALS` に番号が足されます。コミットして公開すると、そのキーは次に
  ページを開いたときから使えなくなります（保存済みのキーも開くたびに検証し直します）。
- 静的なページなので、取り消しは「公開し直したページを開いたとき」に効きます。オフラインのまま古いページ
  （PWA のキャッシュ）を使い続けている端末には届きません。買い切り・少額なので、これで足りるとしています。
- 台帳に取り消し日と理由を記入する。

## 5. 秘密鍵が漏れた・なくしたとき

1. 新しい鍵ペアを作る：`init --key <新しい場所> --force`（公開鍵が置き換わり、発行済みのキーはすべて無効になる）。
2. 台帳の有効なキー（返金・取り消しを除く）を、同じ通し番号で新しい鍵から発行し直し、購入者に送り直す。
3. 公開用のページを作り直して公開する。

## 6. テスト

```sh
node --test test/supporter.test.js                    # キーの発行→検証、改ざん・別鍵・取り消し・形式の揺れ、fail closed、1日の数え方、ゲート、CLI
node scripts/qa-supporter.mjs --out <scratch のフォルダ> # Playwright：テスト鍵のビルドで 21語目のブロック→解除→削除、本番ビルドは「準備中」
```

テストは毎回その場で鍵ペアを作ります。テスト用の公開鍵を差し込んだビルド（`SUPPORTER_PUBKEY=…`）は、
`build-demo.mjs` / `build-pwa.mjs` が `dist/` と `site/` への書き込みを拒否します。
