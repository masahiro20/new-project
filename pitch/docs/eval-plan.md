# 人の声での精度検証 手順書（P3 Pitch）

状態：**保留**。録音者（オーナーの協力）が得られた時点で実施する。
目的：「単語＋が」の下がり目の合否判定が、実際の人の声でどのくらい当たるかを測り、
外部ユーザー5人に出してよい水準かを判断する。

## 1. 何を測るか

| 指標 | 定義 | 目標（ステージ2→外部テスト） |
|---|---|---|
| 正しい発音の合格率 | 辞書どおりに言った録音のうち「合格」になった割合 | **90%以上** |
| 誤った発音の誤合格率 | わざと違う型で言った録音のうち「合格」になった割合 | **5%以下** |
| 型の一致率 | 検出した下がり目 k が、実際に言った k と一致した割合 | 参考値 |
| 判定不能率 | 「声が聞こえない」「短すぎる」になった割合 | 5%以下 |

誤合格（間違っているのに褒める）は学習者の信頼を最も損なうので、誤不合格より厳しく見る。
それぞれ Wilson の 95% 信頼区間を付けて報告する。

## 2. 協力者

- **ネイティブ（基準）**：東京式アクセントの話者 4人以上（女性2・男性2以上、年代を分ける）。
  各自の発音がその語の辞書の型と一致しているかは、後述の聞き取りで確認する。
- **学習者（実地）**：N3〜N1 の学習者 5〜10人（母語を分ける：英語・中国語・韓国語など）。
- 謝礼と同意書が必要（オーナー判断）。同意書には次を入れる：
  - 録音は精度検証のためだけに使い、外部に公開しない。受領から90日で削除する。それより前でも、話者本人の依頼があれば7日以内に削除する（本部決定 d27）。
  - アプリの見本音声に使う場合は、**別途、商用利用の許諾書**を交わす（任意。断っても検証には参加できる）。

## 3. 語のリスト

`docs/eval-words.tsv`（100語。`node scripts/make-eval-list.mjs > docs/eval-words.tsv` で再生成）。

- 平板型・頭高型・中高型・尾高型を **各25語**。1〜5モーラに散らす。
- タグで弱点を測る：`minimal-pair`（箸・橋・端など）、`devoicing-risk`（母音の無声化が起きやすい）、
  `special-mora`（ん・っ・ー）、`vowel-initial`（母音で始まり区切りの手がかりが弱い）、`two-accents`（辞書に型が2つ）。

## 4. 録音のしかた

| 項目 | 条件 |
|---|---|
| 発話 | 「単語＋が」を単独で。例：「はしが」。読み上げのテンポは自然に |
| 回数（ネイティブ） | 正しい型で **2回**、わざと違う型で **1回**（平板⇄下がり目あり。指示は台本で出す） |
| 回数（学習者） | 正しい型を目指して **2回** |
| 機材 | 3種類：ノートPC内蔵マイク／スマホ（ブラウザ）／ヘッドセット |
| 環境 | 静かな部屋（約40dB）と、雑音のある部屋（約60dB、カフェの音を流すなど） |
| 距離 | 口から約30cm |
| 形式 | デモの「audio file」読み込みと同じ形式。WAV、16kHz以上、モノラル推奨 |
| ファイル名 | `<話者ID>_<語no>_<take>_<right\|wrong>_<device>_<room>.wav` |

1人あたりの所要時間はネイティブ約30分（300録音）、学習者約15分（200録音）。

## 5. 正解ラベルの付け方

1. ネイティブの「正しい型」の録音は、辞書の型を正解とする。
2. ただし聞き取りで確認する：別のネイティブ2人が録音を聞き、下がり目の位置を独立に記入する。
   2人が一致し、かつ辞書と同じものだけを「正しい発音」として採点に使う。一致しないものは除外し、件数を報告する。
3. 「わざと違う型」の録音も同様に聞き取りで実際の型を確認し、`spokenK` に記録する。
4. 学習者の録音は、ネイティブ2人の聞き取り結果を正解にする（合格・不合格の両方が出る）。

## 6. 評価のしかた

1. 録音をマニフェストにまとめる（`file, surface, kana, accent, spokenK, speaker, particle: true`）。
2. 実行：
   ```sh
   node scripts/eval-real.mjs manifest.json --swiftf0 --csv results.csv
   ```
   エンジン（pitchy / SwiftF0）× 区切り方（等分 / 手がかり利用）ごとに、型別・モーラ数別の表が出る。
3. 機材・環境・話者・タグごとに CSV を集計し、弱点を特定する。
4. 誤判定は全件、プロット（デモ画面に読み込む）で目視確認し、原因を分類する：
   F0 抽出の失敗／区切りのずれ／無声化／きしみ声／話者の発音自体の揺れ。

## 7. 合否と次の判断

- 目標を満たす：外部ユーザー5人のテストへ進む（公開はオーナー承認後）。
- 誤合格率が5%を超える：判定の閾値（`minStep`）を上げ、「自信が低いときは保留」と表示する。
- 特定の条件だけ悪い（例：雑音環境、スマホ）：その条件の注意書きを出し、改善を次のスプリントに入れる。

## 8. これまでに済んでいる検証（参考）
