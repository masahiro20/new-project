# 建築法令エージェント

住宅・建築会社の社内向けに、「こういう計画をしたい」と入力すると、適用される法令・必要な手続き・注意点・こちらから確認したい質問を**条文の根拠付き**で返す Web アプリです。設計・コーディネーター・施工・営業の誰が使っても同じ根拠に基づく答えが出ることを目的にしています。

## 何を根拠にするか

| 等級 | 内容 | 取得元 |
|---|---|---|
| 【条文】 | 法律・政令・省令の現行条文（一次情報） | [e-Gov 法令API v2](https://laws.e-gov.go.jp/)。条単位で取得し、条番号・数値はここで裏付ける |
| 【公的】 | 国土交通省・消防庁・農林水産省・環境省・都道府県・市区町村の公式資料 | 知識ベースに登録した URL と、エージェントの Web 検索（go.jp / lg.jp 等を自動判定） |
| 【参考】 | 業界団体・解説記事など | 公的根拠を探す手がかりのみ。単独の根拠にはしない |

- 知識ベース `lib/knowledge.ts` の全ルール（約70項目）は、法令ID・条番号・条見出しを登録しており、`npm run verify-sources` で e-Gov の現行条文と照合します（2026-10-18 時点で 55法令・171条、不一致 0）。照合結果は `data/law-snapshot.json` に保存され、改正で現行版が変わると検知されます。
- エージェント（Claude）は回答時にも `get_law_article` ツールで条文を取得してから書く設計で、条例・自治体運用は Web 検索で公式ページを探し、見つからなければ確認先の窓口を示します。

## 住所から環境を自動把握する仕組み

| 情報 | 取得元 | キー |
|---|---|---|
| 住所 → 緯度経度 | 国土地理院 住所検索API | 不要 |
| 区域区分・用途地域（建蔽率・容積率）・防火指定・地区計画・立地適正化計画・都市計画道路 | 国土交通省 不動産情報ライブラリ API（都市計画決定GISデータ 令和7年度） | **必要**（無料・申請制） |
| 土砂災害警戒区域／特別警戒区域、洪水・津波・高潮浸水想定、災害危険区域、大規模盛土造成地、地すべり防止区域、急傾斜地崩壊危険区域、自然公園 | 同 API（国土数値情報） | 同上 |

- `/api/site?address=…` が上記をまとめて取得し、地点がどのポリゴンに含まれるかを判定して「区域区分・用途地域・防火指定・該当区域」を返します。手入力は自動取得を上書きできます。
- 調べられないもの（登記の地目、農用地区域、前面道路の法上の種別・幅員、法22条区域、埋蔵文化財包蔵地）は入力欄か「要確認」として残します。
- API キーは https://www.reinfolib.mlit.go.jp/ の「API利用申請」から取得し、環境変数 `REINFOLIB_API_KEY` に設定します（発行まで数営業日）。未設定でも、位置特定と手入力ベースのチェックは動きます。

## 画面

| パス | 内容 |
|---|---|
| `/consult` | 住所＋「何を建てたいか」を入力 → 環境の自動取得 → 即時ルールチェック（右側）→「法令チェックを実行」でストリーミング回答＋参照した根拠一覧 |
| `/rules` | 知識ベースの全ルールと根拠条文（サイト内で現行条文を表示／e-Gov リンク） |
| `/law/[法令ID]/[条]` | e-Gov から取得した現行条文の表示 |
| `/sources` | 根拠の等級、照合の仕組み、法改正への対応、引用法令・公的資料の一覧 |

API: `GET /api/site?address=`（環境の自動取得）、`POST /api/consult`（NDJSON ストリーム）、`GET /api/law?law=建築基準法&article=43`（条文）、`?title=`（法令検索）、`?keyword=`（全文検索）。

2025年4月施行の建築基準法・建築物省エネ法改正（新2号・新3号建築物、省エネ基準適合義務化、壁量計算の見直し）を前提にしています。

## ローカルで動かす

```bash
cd kenchiku-law-agent
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY を記入
npm run dev                  # http://localhost:3000
```

API キーがなくても、即時ルールチェック・知識ベース・条文表示は動きます（エージェント回答のみキーが必要）。

## チェック

```bash
npm run typecheck
npm test                 # ルールエンジン・入力スキーマ・Markdown のユニットテスト
npm run verify-sources   # 全引用条文を e-Gov と照合し data/law-snapshot.json を更新（--check で照合のみ）
npm run build
```

## 公開（社内利用）

1. Anthropic Console で API キーを発行し、環境変数 `ANTHROPIC_API_KEY` を設定
2. Vercel 等にこのリポジトリを接続し、**Root Directory を `kenchiku-law-agent`** に設定
3. 社内限定にするなら `ACCESS_PASSWORD` を設定（画面にアクセスキー欄が出ます）。より確実にはホスティング側の認証（Vercel の Deployment Protection など）を併用
4. 月1回 `npm run verify-sources -- --check` を実行し、改正・条番号変更を検知したら `lib/knowledge.ts` を更新

## 構成

```
lib/laws.ts        引用する法令の e-Gov 法令ID
lib/egov.ts        e-Gov 法令API v2 クライアント（条文取得・法令検索・全文検索）
lib/plan.ts        入力スキーマ（zod）
lib/knowledge.ts   ルール知識ベース（条文・公的資料の根拠付き）
lib/rules.ts       ルールエンジン（即時チェック）
lib/prompts.ts     エージェントのシステムプロンプト（根拠の原則・出力形式）
lib/agent.ts       Claude エージェントループ（e-Gov ツール＋Web 検索／取得、NDJSON ストリーム）
scripts/verify-sources.ts  条文照合スクリプト
data/law-snapshot.json     照合済み条文のスナップショット
```

## 限界

- 条例（がけ条例・日影・景観・火災予防条例・開発許可の条例区域・最低敷地面積など）は自治体ごとに異なり、網羅していません。該当の可能性と確認先を示します。
- 告示・技術的助言は e-Gov 法令API の対象外です。必要な場合は国交省等の公式ページを参照します。
- 許可の可否を保証するものではありません。最終判断は所管窓口への確認と建築士の判断で行ってください。
