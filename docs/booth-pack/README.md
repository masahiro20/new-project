## 3. どう作ったか（購入後の AI 生成・Stripe は不使用。作成には AI の支援を使用）

- 文章は、公開済みの無料テンプレート（`lib/templates/*`）の出力をそのまま使用。**新しく書いたのは、使い方1枚、チェックリスト追加編、記入例の架空の値**だけです。
- 記入例は、無料テンプレートの【要記入】を、架空の値で埋めて作りました（`scripts/booth-pack/example.ts`）。事業所名・氏名・日付・会議の内容は架空です。研修の事例検討は、無料版と同じ「サービス種別ごとの事例」（`service-examples.ts`）を使っています。
- **身体拘束等の記録様式とご説明書には、記入例を載せていません**（実際の事案を想定した例は誤用につながるため）。無料版の見本（/samples）と同じ方針です。理解度テストの回答欄も白紙です。
- PDF は Chromium（Playwright）で、Word は無料版と同じ `lib/docx-export.ts` で作成。チェックリスト本編は、公開済みの無料版（public/downloads の Word）の文章を `scripts/booth-pack/checklist-main.md` に起こし、下の §4 の2か所だけ直して作り直した（レイアウトは無料版と異なる）。

作り直す手順：

```bash
npm ci
npx esbuild scripts/booth-pack/build.ts --bundle --platform=node --format=esm --outfile=.booth/build.mjs --log-level=warning --external:playwright
OUT_DIR=/tmp/booth PLAYWRIGHT_MODULE=<playwright の index.mjs> CHROMIUM_PATH=<chromium の実行ファイル> node .booth/build.mjs
# → /tmp/booth/減算ゼロ_書類パック_2026年10月版.zip
```

**断定していない点**（パックにも断定して書いていません）：

- 令和8年6月の特例が、児童発達支援管理責任者の欠如に使えるか（通知の文言上は対象外と読めるため、「指定権者に確認」）。
- 欠席時対応加算の単位数・月の回数の上限（告示の原文を確認できていないため、パックには載せず「告示と指定権者の案内で確認」）。
- 勤務形態一覧表の端数処理、記入する期間（自治体の様式で異なる）。
- 議事録・記録の保存期間（条例で定める。パックでは「指定権者の条例で確認」）。

**減算率の確認（本部の指示 d35、2026-10-14）**：上の表のとおり、無料テンプレートの本文とチェックリストの減算率は、令和8年度改定後の留意事項通知（通所は5月28日改正後、障害福祉サービスは4月2日改正後）と一致しました。数字の変更はありません。報酬告示そのもの（官報の画像PDF）は読めなかったため、**告示ではなく、告示に基づく留意事項通知の記述で裏付けています**。

**確認の結果、直した点**（パックのチェックリスト本編）：

1. 「情報公表未報告減算も、事実が生じた時点までさかのぼる」とだけ書いていた点を、Q&A 問19 のとおり「報告していないことが確認され、報告するよう指導されても報告しない場合に、未報告の時点にさかのぼる」に直した（業務継続計画未策定減算は問15）。
2. 「減算せずに請求していた場合は、返還の対象になりえます」を、「請求の修正などの取扱いは指定権者に確認」に直した。返還（さかのぼり）の記述は、本部の決定（docs/decisions.md の #14）で、専門家の確認まで書かないことになっているため。

**公開中の無料版チェックリスト（public/downloads の PDF・Word）も、同じ内容に直しました**（本部の指示。2026-10-14）。パックと同じ `scripts/booth-pack/checklist-main.md` から作り直したため、レイアウトは以前と異なります（3ページ）。元の PDF の元データは peter/hq-revenue ブランチにあり、そちらは変更していません。作り直しは `FREE_CHECKLIST=1`（または `ONLY_FREE=1`）を付けて build を実行します。

**まだ確認していない点**：

1. 無料テンプレート全体の制度記述（運営基準・通知の引用）は、公開時に一次資料で確認する運用で作られています。パックでは、減算率と起算月の記述だけを再確認しました。オーナーの確認前に、ほかの箇所の抜き取り確認（2〜3か所）を推奨します。
2. 報酬告示の本文（単位数・欠席時対応加算の回数上限など）。パックには載せていません。

## 7. サイトの案内（BOOTH のパックへのリンク）

- 全解説記事の末尾（関連する解説の下）と、無料テンプレートのページ（/templates）に、小さな案内を出す（`app/BoothPromo.tsx`）。中身は「サービス種別ごとの記入例つき書類パックはこちら」、要点3つ、価格と販売者、BOOTH への1ボタン。煽る表現は使わない。
- **商品ページの URL は `lib/booth.ts` の `BOOTH_URL_SETTING` の1か所だけ**で決める（ビルド時に `NEXT_PUBLIC_BOOTH_URL` で上書きもできる）。
- **URL が決まるまで、案内はサイトに出ない**。仮置き `{{BOOTH_URL}}` のままか、`booth.pm` の https の URL でなければ、何も描画しない。
- `npm run export:pages` の最後に `scripts/check-booth-placeholder.mjs` が出力を点検し、`{{BOOTH_URL}}` が残っていたら失敗にする。案内を出す公開では `BOOTH_REQUIRED=1` を付けると、リンクが1つも無い場合も失敗にする。テストは `tests/booth.test.mjs`。
- 公開の手順：`lib/booth.ts` の `BOOTH_URL_SETTING` に URL を入れる → `BOOTH_REQUIRED=1 npm run export:pages` → gh-pages に公開。クリックは、分析が有効なとき `cta-booth` として数える。
- note の下書き（`docs/note-drafts.md`）の記事4〜6の末尾にも、同じ案内文を入れた。URL は `{{BOOTH_URL}}` の仮置きで、投稿前に置き換える。
