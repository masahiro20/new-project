# 毎週月曜の収益週報

| ファイル | 役割 |
|---|---|
| `metrics.csv` | **実績の記録**。1行＝1つの数字（週の最終日、PJ、指標、値、出典）。推測の数字は入れない |
| `targets.csv` | 目標。`revenue-map`、`p0-growth.md`、`p8-launch.md` の数字から作った |
| `build_weekly.py` | `python3 build_weekly.py <日曜の日付>` で `reports/<月曜の日付>.md` を作る。表と未計測の一覧は自動で、要点・打ち手・お願いは手で書く |
| `reports/` | 作った週報 |

## 毎週の手順（月曜の朝）
1. 数字を集めて `metrics.csv` に足す。
   - 各チームの報告、Search Console、アクセス解析、itch・BOOTH・Stripe の画面（オーナーから共有されたもの）。
2. `python3 build_weekly.py 2026-10-18` を実行する（例は 10/19 の週報の場合）。
3. 要点・ゲート・打ち手・お願いを書き、ダッシュボードを更新し、本部に1〜2行で報告する。

## 指標の名前（そろえる）
`targets.csv` の「指標」と同じ名前を使う。新しい指標は、そのまま `metrics.csv` に書けば「目標なし」の行として表に出る。

## 第1号
**2026-10-19（月）**：対象は10/13〜10/18。P0 と P8 の初週の数字が入る。

## 数字の集め方（10/19 の第1号から）
毎週日曜の夜までに、各チームのリーダーが自分の数字を本部（Midas）に1行ずつ送る。
- 形式：`週の最終日,PJ,指標,値,出典`
- 例：`2026-10-18,P8,ブラウザでのプレイ,312,itch.io の管理画面`
- オーナーにしか見られない画面（売上・入金）は、オーナーが月曜の朝に件数だけを伝える。

| PJ | 指標 | 担当 | 出典 | 今の状態 |
|---|---|---|---|---|
| P0 | サイト訪問 | Mina | Cookie を使わないアクセス解析 | **未設置**。P0 のバックログ①（計測）で入る予定 |
| P0 | 無料診断の完了、見本の保存 | Mina | 同上（ボタンと結果画面のイベント） | **未設置**。同上 |
| P0 | Search Console クリック | Mina | Google Search Console | オーナーの登録待ち |
| P0 | 購入・売上 | オーナー | Stripe の管理画面 | 有料版の開始後 |
| P2 | 計算機の訪問 | Vega | アクセス解析 | **未確認**。計算機は「読み込み後に通信しない」設計なので、計測の方法を Vega が決める（ページの外側で数えるなど） |
| P2 | Budget Guard の待機リスト・有料利用 | Vega | 待機リストの保存先、Stripe | 待機リストのページの公開後 |
| P8 | itch のページ閲覧・プレイ・投げ銭 | P8 リーダー | itch.io の管理画面（Analytics） | 10/13 の公開後。管理画面を見られるのはオーナーなので、件数をオーナーから受け取る |
| P7 | Vol.0 の販売、商品ページの閲覧 | オーナー | BOOTH・Ko-fi の管理画面 | 10/22 の発売後 |

**計測していない数字は「未計測」と出す。** 推測の数字は入れない。第1号（10/19）は、P0 の計測が間に合わなければ、ほとんどが「未計測」になる見込み。その場合、計測の遅れを週報のいちばん上の課題として書く。
