# Codex 用プロンプト：note 連載の投稿自動化ツールを作る

以下をそのまま Codex に貼ってください。`{{ }}` の部分だけ、自分の環境に合わせて書き換えてください。

---

あなたは私のパソコン上で動く開発アシスタントです。note.com に短編小説の連載を投稿する作業を、できる限り自動化するツールを作ってください。日本語で報告してください。

## 背景
- note で短編小説シリーズ『その係、事件の第一発見者です』を連載しています。週2回（火・金）更新です。
- 原稿、表紙画像、X の投稿文は、すでにフォルダに用意されています。私の作業は「貼って公開する」だけですが、それでも毎回10分かかるので、ここを自動化したいです。
- note には公式の投稿 API がありません。そのため、私自身がログイン済みのブラウザを、私のパソコン上で自動操作する方法で進めてください。ログイン情報（メールアドレス・パスワード）はツールに保存しないでください。
- note の利用規約に、ブラウザの自動操作を禁じる条項がないか、最初に確認して報告してください。禁じられている場合は、実装せず、理由と代替案（下書き作成までで止める等）を提示して止まってください。

## 素材の場所
- 原稿フォルダ：`{{/path/to/note-ready}}`
  - `epNN_タイトル.txt` … 1行のタイトル
  - `epNN_本文.txt` … 本文（プレーンテキスト。段落は空行区切り。見出しや装飾はなし）
  - `epNN_表紙.png` … 見出し画像（1280×670 または 1920×1005）
- 共通設定：`{{/path/to/note-ready}}/series.json`（なければ作ってください）
  ```json
  {
    "magazine": "その係、事件の第一発見者です",
    "hashtags": ["その係事件の第一発見者", "短編小説", "ミステリー", "お仕事小説"],
    "price_from_episode": 6,
    "price_jpy": 200,
    "free_preview_ratio": 0.3,
    "schedule": { "weekdays": ["Tue", "Fri"], "time": "07:30", "timezone": "Asia/Tokyo" }
  }
  ```
- X 投稿文：`{{/path/to/x-posts.md}}`（日付ごとの見出しの下に本文。`（note のリンク）` は公開した記事の URL に置き換える）

## 作ってほしいもの
### 1. `note-post` コマンド（Node.js + Playwright、または Python + Playwright）
- `note-post draft ep03` … 第3話の下書きを note に作る。タイトル、本文、見出し画像、ハッシュタグ、マガジンへの追加、まで行い、**公開はしない**。作った下書きの URL を表示する。
- `note-post publish ep03 --at "2026-11-03 07:30"` … 下書きを、指定日時で予約公開する（noteプレミアムの予約投稿機能を使う。プレミアムでない場合は、その旨を表示して、公開ボタンを押さずに止まる）。
- `note-post publish ep03 --now` … 即時公開する。実行前に、タイトル・公開設定・価格を画面に表示して、`y` を入力したときだけ公開する。
- `--dry-run` … ブラウザを動かすが、保存・公開は一切しない。各ステップで何をするかを表示する。
- 有料設定：`price_from_episode` 以上の話は、価格を `price_jpy` にして、本文の先頭から `free_preview_ratio` の位置に有料ラインを入れる。無料の話は、有料設定をしない。
- 本文の貼り方：改行と空行がそのまま note の段落になること。文字化けや全角スペースの欠落がないこと。貼り付け後に、note 上の本文の文字数と元ファイルの文字数を比べて、差があれば警告する。
- 同じ話を二重に下書きしないこと。作成済みの下書き URL は `state.json` に記録し、2回目は既存の下書きを開いて更新する。
- ログイン：Playwright の永続プロファイル（`userDataDir`）を使う。初回は `note-post login` でブラウザを開き、私が手動でログインする。以降はそのプロファイルを再利用する。プロファイルのフォルダは `.gitignore` に入れる。
- 画面の構造が変わって要素が見つからないときは、スクリーンショットを `logs/` に保存して、どの手順で止まったかを日本語で表示して終了する。無理に進めない。

### 2. `x-post` コマンド（X の公式 API を使う）
- X の開発者アカウントの API キーを、環境変数（`.env`、`.gitignore` 済み）から読む。
- `x-post queue` … `x-posts.md` を読み、日付と時刻ごとの投稿を `queue.json` にする。`（note のリンク）` は `state.json` の公開済み URL に置き換える。
- `x-post run` … 現在時刻を過ぎていて未投稿のものを投稿する。投稿済みは `queue.json` に記録して二重投稿しない。
- `x-post preview` … 今週投稿する予定の文面を一覧表示する（私が目を通すため）。
- 定期実行：macOS なら `launchd`、Linux なら `cron`、Windows なら「タスク スケジューラ」で、`x-post run` を30分ごとに動かす設定ファイルと登録手順を作る。

### 3. 週1回の手順書 `WEEKLY.md`
- 私が週に1回やることを、コマンドの順に書く。目標は15分以内。
  1. `x-post preview` で今週の X の文面を確認
  2. `note-post draft epNN` を今週分（2話）実行
  3. ブラウザで下書きを目視確認
  4. `note-post publish epNN --at ...` で予約
  5. `x-post queue`

## 守ってほしいこと
- 認証情報、Cookie、プロファイルは、絶対にリポジトリにコミットしない。`.gitignore` を最初に書く。
- 公開・課金設定の変更など、取り消しにくい操作の前には、必ず内容を表示して確認を取る（`--yes` を付けたときだけ省略可）。
- note と X の規約に反する動き（大量投稿、他人のアカウント操作、レート制限の回避）は実装しない。
- 依存パッケージは最小限にする。README に、インストールから初回ログインまでの手順を日本語で書く。
- 各コマンドに `--help` を付ける。エラーメッセージは日本語で、次に何をすればよいかを書く。

## 受け入れ条件（これが通れば完成）
1. `note-post draft ep01 --dry-run` が、ブラウザを開いて各ステップを表示し、何も保存せずに終わる。
2. `note-post draft ep01` が、note に下書きを1件作り、タイトル・本文・画像・タグ・マガジンが正しく入っている（私が目視で確認）。本文の文字数の差がゼロ。
3. 同じコマンドをもう一度実行しても、下書きが増えない。
4. `note-post publish ep01 --at "<未来の日時>" --dry-run` が、予約の画面まで進んで止まる。
5. `x-post preview` が今週分の文面を表示し、`x-post run --dry-run` が投稿せずに対象一覧だけ表示する。
6. `WEEKLY.md` の手順どおりにやって、15分以内で2話分の予約と X の準備が終わる。

まず、実装の前に、次の3点を調べて報告してから着手してください。
- note の利用規約・ヘルプにおける自動操作の扱い
- note の投稿画面で、予約投稿・有料設定・マガジン追加がどの順番で出るか（スクリーンショットつき）
- X API の無料枠で、月に何件投稿できるか（公式ページの記述を引用）

## 補足（ピーターから、あなたへ）
- このプロンプトは、あなたのパソコンで Codex を動かす前提です。ログイン済みのブラウザが、あなたの手元にあるからです。私（クラウド上のピーター）からは、あなたのブラウザに触れません。
- 原稿の場所は、リポジトリの `peter-hq/novel/note-ready/` です。パソコンに clone してあれば、そのパスを `{{/path/to/note-ready}}` に入れてください。
- X の API キーを使う場合、X の開発者登録（無料）が先に必要です。登録ページで「無料プラン」を選び、アプリを1つ作って、鍵4つ（API Key、API Secret、Access Token、Access Token Secret）を発行してください。鍵は `.env` にだけ置き、誰にも送らないでください。
- 「note の規約で禁じられていたら止まる」という条件は、外さないでください。アカウントは連載の土台なので、守るのが最優先です。
