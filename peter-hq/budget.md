# 使用量の運用ルール（2026-10-09 オーナー指示）

オーナーの方針：「プロジェクトは止めない。ただし、週の使用量を上回らないこと。特に、週の終わりの2〜3日前に残りがゼロになって止まるのは避ける。夜中など使っていない時間帯は、どんどん進めてよい」

## 使用量の段階（週の使用率で決める）
| 週の使用率 | 段階 | 動かすもの |
|---|---|---|
| 〜60% | 通常 | 売上に近い3チームまで同時に動かす（P0 → P1 → P8 → P2 の順） |
| 60〜80% | 節約 | 1〜2チームだけ。期限のある作業を優先する |
| 80%〜 | 最小 | 期限が迫った作業を1件だけ。毎晩の報告は短くする |
| 週の残りが2〜3日 | 予備を残す | 新しい作業は始めない。オーナーが日中に使う分（20%以上）を残す |

- 夜中（日本時間 0〜7時）は、オーナーが使わない時間なので、段階が許す範囲で優先的に作業を割り当てる。
- ピーターには週の使用率が直接見えない。オーナーから使用率を聞いたら、この表に当てはめる。聞けていないときは、1段階控えめに動く。

## 節約のやり方
1. 毎時の巡回はしない。ピーターが動くのは、毎晩の報告1回と、オーナーやチームから連絡があったときだけにする。
2. チームには「1件終わったら報告して止まる」形で任務を出す。自分で次の作業を始めるのは、通常段階のときだけ。
3. サブエージェントを並べて動かす作業や、大規模なテスト（毎回の全件・3回連続など）は、本当に必要なときだけにする。
4. 報告は短く。再公開のあとの確認は、1回の取得で済ませる。
5. 当面やらないこと：見た目の作り込み（オフィスの3D など）、点検の再点検、売上に直結しない調べもの。
6. Midas の夜の情報収集は止める。最先端情報は、毎晩の報告の中で軽く扱う。
